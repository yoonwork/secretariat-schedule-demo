1. 기술 스택과 고른 이유

화면
React + TypeScript휴대폰·PC 반응형이고, 2단계 기능(결재·업무 관리)을 붙이기 쉬운 구조예요.
서버·DB
Supabase (PostgreSQL)로그인, 권한, DB를 한 번에 제공해서 직접 관리할 서버가 없어요.
배포
Cloudflare Pages소스를 올리면 자동으로 배포되고, 단체·상업용도 무료예요.
  • 직원 10명 규모면 무료 요금제 안에서 운영돼요. 사용량이 늘면 그때 유료로 바꾸면 돼요.
  • 표준 SQL DB예요. 나중에 업무 요청·결재, 워크로드 분석을 붙일 때 일정·미팅 데이터를 그대로 이어서 써요.
  • 권한은 DB에서 막아요. 등록한 사람과 사무국장만 고치고 지울 수 있게 해요.
  • 소스는 학회 소유 GitHub 저장소에 올리고, DB 스키마와 배포·운영 안내서를 함께 드려요.

2. 이게 되면 성공이라고 봐요

  • 메일이 줄어요. 직원 10명이 각자 일정과 미팅을 직접 등록하고, 사무국 전체 일정을 달력 한 화면에서 봐요.
  • 입력이 1분 안에 끝나요. 일정 하나 등록하는 데 필요한 칸만 남겨요. 휴대폰에서도 똑같이 돼요.
  • 오늘 할 일이 바로 보여요. 로그인하면 오늘 일정, 이번 주 내 일정, 다가오는 학술대회 D-day가 첫 화면에 떠요.
  • 미팅 기록이 남아요. 미팅마다 참석자, 안건, 회의 메모가 한곳에 쌓여요.
  • 개발자 없이도 운영돼요. 직원 계정 추가와 비밀번호 초기화를 사무국에서 직접 할 수 있고, 그 방법이 안내서에 있어요.
  • 실제 사용 테스트를 해요. 오픈 전에 사무국 직원 2~3명이 1주일 써 보고, 불편한 점을 고친 뒤에 끝내요.

3. 일정 (30일)

1주차
이 데모를 함께 보며 화면 구성과 일정 분류를 확정해요. 기능 목록 전체를 보고 2단계까지 고려해 DB를 설계해요.
2주차
로그인, 일정 등록·조회, 달력 화면을 개발해요. 중간 결과를 주소로 공유해요.
3주차
내부 미팅 등록·조회, 회의 메모, 권한을 개발하고 배포해요.
4주차
직원 시범 사용, 수정 반영, 소스·DB 스키마·운영 안내서를 전달해요.
